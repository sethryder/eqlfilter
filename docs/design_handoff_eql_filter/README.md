# Handoff: EQLFilter — EverQuest Legends Loot Filter Builder

## Overview
EQLFilter (eqlfilter.washclof.com) is a web app for building, saving, and sharing **loot filters** for the game *EverQuest Legends*. EQL lets players automate item handling — Loot, Merge, Store, or Sell — per item, stored in an INI file. This app gives players a visual builder: search a catalog of in-game items, assign one action to each, and export the result as an INI, a shareable link, or save it locally to switch between multiple named filters.

The single-screen app is split into three regions:
- **Item Library** (left) — searchable, filterable catalog; click to add items.
- **Your Filter** (right) — the rules you've built, each with a mutually-exclusive action selector.
- **I/O panel** (bottom) — INI export / import / share-link, in a resizable drawer.

## About the Design Files
The files in this bundle are **design references created in HTML** — a working prototype that demonstrates the intended look, layout, and behavior. They are **not production code to copy directly.**

The prototype is authored as a "Design Component" (`EQL Filter.dc.html`) that runs on a small bespoke runtime (`support.js`). **Do not ship `support.js` or the `.dc.html` format.** Instead, **recreate this design in the target codebase's environment** using its established framework and patterns. The logic is plain React-class-style state, so it ports cleanly to React, Vue, Svelte, etc. If no codebase exists yet, **React + TypeScript + Vite** is the recommended choice; the component model maps 1:1.

To preview the prototype: open `EQL Filter.dc.html` in a browser (it loads `eql-items.json` from the same folder; serve over `http://` rather than `file://` so the fetch succeeds).

## Interactions & Behavior

- **Add item**: click a library row, press Enter in search, or click "Add custom item". Adds with the current **add-as** action. Duplicate names (case-insensitive) are silently ignored.
- **Change a rule's action**: click one of its 4 action buttons. Mutually exclusive.
- **Remove a rule**: the "×" button on the row.
- **Apply to all**: sets an action for every catalog item matching the current search+zone+category filter (adds + retags). Count is shown in the label so users see the blast radius before clicking.
- **Summary-chip filtering**: clicking an action summary chip filters the visible rules to that action; toggle off by clicking again or via "Show all".
- **Clear items**: empties rules of the current filter.
- **Light/Dark toggle**: swaps the entire theme; persists to localStorage; defaults to dark.
- **Saved filters**: Save (insert or update by id), Load (replace working state), Delete, New (blank filter). Menu dismiss on outside-click/Escape.
- **Resizable I/O drawer**: drag handle (90–620px) or Expand/Collapse toggle (560px).
- **Export**: Copy INI (clipboard) or Download .ini (Blob download, filename = sanitized filter name + `.ini`).
- **Import**: paste INI text → Load filter parses it and replaces name + rules.
- **Share**: generates a URL with the entire filter base64-encoded in the hash (`#f=…`); copying gives a link that restores the exact filter on load.

### Restore priority on load
1. **Shared link** (`#f=` hash) — wins if present.
2. **Saved working draft** (localStorage) — restores unsaved in-progress work.
3. **Defaults** — the seed filter.

## State Management

Component state (all client-side; no backend):
- `name` (string) — current filter name.
- `rules` (array of `{ name, action }`) — the filter. `action ∈ {Loot, Merge, Store, Sell}`.
- `query` (string), `cat` (string), `zone` (string) — library filters.
- `addAction` (string) — action applied to newly added items.
- `ruleFilter` (string) — `"All"` or an action; filters the rules list.
- `saved` (array of `{ id, name, rules, updated }`) — saved filters.
- `currentId` (string|null) — id of the loaded saved filter, for dirty-tracking.
- `menuOpen` (bool) — saved-filters dropdown.
- `panel` (`"ini"|"import"|"share"`) — active I/O tab.
- `importText` (string), `copied` (string key) — transient I/O state.
- `ioHeight` (number px), `ioMax` (bool) — resizable drawer.
- `mode` (`"dark"|"light"|null`) — theme; null falls back to default (dark).

**localStorage keys** (all written by the app; namespace-prefixed):
- `eqlfilter.saved.v1` — array of saved filters.
- `eqlfilter.draft.v1` — `{ name, currentId, rules }` working draft, written on every change.
- `eqlfilter.mode.v1` — `"dark"` | `"light"`.

**Data loading**: catalog is fetched from `eql-items.json` on mount; an inline ~42-item fallback renders if the fetch fails.

**Dirty tracking**: a filter is "dirty" if no `currentId`, or its name/rules differ from the saved copy. Drives the Save button label.

## Item Data Schema (`eql-items.json`)
Array of objects:
```json
{ "name": "Onyx Earring", "type": "Jewelry", "slot": "Ear", "zone": "Blackburrow", "flags": ["MAGIC"] }
```
- `type` ∈ the type-color set above (drives icon color + category filter).
- `slot` — equipment slot or role string (free text, shown in subtitle).
- `zone` — source zone (drives the Zone filter; may be `""` for items not yet zone-tagged).
- `flags` — array of `NO DROP | LORE | MAGIC | QUEST` (shown in subtitle; relevant to loot decisions, e.g. NO DROP can't be vendor-sold).

### Generating the full catalog
`tools/build-eql-items.mjs` (Node 18+, no npm deps) scrapes the EQL Wiki MediaWiki API:
```
node tools/build-eql-items.mjs > eql-items.json
```
It enumerates all items under `Category:Items` (~10,600), tags `type` from the wiki's type-subcategories, and parses slot/flags from each item page. **Caveat**: the per-page `slot`/`flags` parsing depends on the wiki's item template, which wasn't visible at authoring time — run `node tools/build-eql-items.mjs --inspect "Onyx Earring"` to dump one page's wikitext, then tune the regexes in `parseItem()`. Item enumeration and type-by-subcategory work as-is. Zone backfill (walking each zone's "Known Loot" table) is a TODO noted in the script.
